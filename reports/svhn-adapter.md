# SVHN cropped-digit adapter receipt (2026-09-22)

The local `svhn` adapter now browses a pinned **train plus test** population from the [original Stanford cropped 32×32 MAT release](http://ufldl.stanford.edu/housenumbers/). It does not claim the separately published 531,131-image `extra` split or the full-number PNG/bounding-box representation. The source page limits use to noncommercial purposes; the 100 PNG derivatives are local inspection media, and the registry keeps public publication at `metadata_only` pending an explicit image-rights decision.

Transfers were byte-capped to the source HEAD lengths, resumed only against the exact URL and a matching `Content-Range`, and rejected redirects. The original host serves HTTP; its HTTPS certificate did not match the host. The independently listed MD5 values were checked on the downloaded bytes, then SHA-256 values pinned for subsequent local preparation. Original MAT files remain unchanged under `work/sources/svhn/`, with receipts in `download-receipts.json`. No `extra` transfer was attempted.

`SVHNAdapter` verifies sizes and both digests, uses SciPy's MAT reader only after verification, checks `X` as `uint8[32,32,3,N]` and `y` as `uint8` in `1..10`, and stages row-major RGB pixels plus original label bytes. It exposes stable source-position IDs, a bounded cursor, and per-image PNG derivatives. Records carry both `source.raw_label` and `source.digit`; raw `10` maps to digit `0`, while values `1..9` remain unchanged. A staged manifest pins derived-file hashes so a corrupt prepared cache is rebuilt from the verified originals. SciPy is an optional preparation dependency and is not imported for registry listing.

The local preview `work/packs/svhn/pack.json` contains **100 records and 100 distinct images** from source-order train positions, with all ten normalized digits represented; it is not a prevalence estimate.

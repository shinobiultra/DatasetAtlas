# Built-in analysis processors

`src/dataset_atlas/models.py` defines records, runs, and artifacts. The jobs coordinator freezes the selected IDs and snapshots, then calls `dataset_atlas.processors.run_processor(processor_id, records, config, should_cancel=...)`. The returned JSON body has `processor_id`, `schema_version`, `unit`, `items`, `provenance`, and `coverage`. Every selected record has exactly one item with its stable ID, state, and output. The coordinator registers the durable `Run` and `Artifact`; processors do not write to originals or register their own artifacts. `get_processor(id)` exposes `describe`, `validate_inputs`, `estimate`, and `run_batch` for callers needing the common protocol.

The trusted allowlist is in `processors/core.py`; `registry/processors/builtins.yaml` lists the installed built-ins. Dataset packs cannot name executable code. New processors should declare input units, dependency and device needs, output schema, deterministic configuration, and a bounded resource estimate. Add a small, real contract test, including missing inputs and partial failures. Keep large libraries behind optional imports.

`quality.basic` reads local image assets inside explicit `asset_roots`. It reports oriented dimensions, aspect ratio, file and pixel SHA-256, and a 64-bit difference hash. A failed decode has `failed`; a missing hydrated asset has `skipped`; a record without image assets has `not_applicable`. SHA-256 verified duplicate assets share processing. Originals are read-only. Image processing is capped by `max_pixels` (default 50 million) and file size (100 MB). If an asset declares `sha256`, the bytes must match.

`detect.nudenet` requires `model_path` and `model_sha256` for a locally installed ONNX model. Its current postprocessing has a hardcoded 0.25 NMS score floor, so the adapter rejects lower extraction thresholds and records this floor. `detect.coco_v1` requires `weights_path` and `weights_sha256` for Torchvision's Faster R-CNN MobileNet V3 320 FPN `COCO_V1` weights. The full hash must match the local file, and the Torchvision hash must begin with the official `907ea3f9` prefix. Neither adapter downloads a model. Outputs retain each detection's class, score, and `xyxy` box in **EXIF-transposed image pixels**. `extraction_threshold` is saved in provenance; display thresholds cannot recover detections discarded by extraction. A completed zero-detection result has `detections: []`, unlike an unavailable asset. Person count is a versioned derived value and carries a completeness flag when some assets fail.

`embed.minilm` and `embed.siglip2` require an explicit local snapshot folder, pinned `model_revision` from `registry/models/`, and the full SHA-256 of its `model.safetensors` file. They use local-only loaders, disable remote code, normalize vectors to unit length, and record an `embedding_space_id` derived from the representation recipe. Supplementary tokenizer and config files are copied from no-follow reads into a bounded temporary snapshot before a model library opens them. `representation` is exactly `text` or `question` for MiniLM and `image`, `text`, or `question` for SigLIP 2; labels, filenames, and captions are never silently mixed in. Image mode retains vectors by asset ID and places a single vector on the record when it has exactly one image. SigLIP 2 image and text outputs have distinct representation IDs; `compatible_siglip2_spaces` checks the shared model revision, weight digest, dimension, pooling, normalization, and distance metric before a cross-modal pairing. Equal dimensions alone never imply compatibility. The local snapshot content hash is authoritative because a copied directory name cannot prove its Hub revision. The pinned revisions identify the upstream recipes, while the required file digest identifies the actual local weights. Install optional libraries and prepare a bounded local snapshot explicitly before running.

`project.pca`, `project.umap`, `cluster.kmeans`, and `outlier.knn` take `config.vectors` keyed by selected stable record ID, plus `embedding_space_id` and `embedding_run_id`. They never infer compatibility from dimension. Their item outputs are respectively `{x,y}`, `{x,y}`, `{cluster}`, and `{outlier_score}`. All save selected/fitted IDs, snapshots, original dimension, input digest, method and parameters. PCA uses centered NumPy SVD with a fixed sign convention. UMAP records its seed, metric, neighbours, minimum distance, version, and single-thread setting. K-means uses seeded Lloyd iteration in the original space. The outlier score is distance to the kth other selected vector, in the original embedding space. Refit produces a new `fit_id`; recolouring or hiding points does not invoke a fit. Missing vectors produce `not_applicable` items. Analysis is limited to two million numeric values; exact pairwise outlier analysis is limited to 5,000 rows.

`exact_lancedb_search(table, vector, eligible_ids, limit, metric=...)` is the optional retrieval adapter. The caller resolves an external filter to eligible IDs first. The adapter applies those IDs as a **prefilter**, calls `bypass_vector_index()` for an exhaustive query, and verifies every returned ID belongs to the eligible set. Above 1,000 IDs, build a validated search snapshot rather than silently running a global query and post-filtering. Portable vectors remain the source artifact; LanceDB tables are rebuildable indexes.

`encode_text_query(artifact, source_run_config, text)` loads the same pinned local model and encodes at most 4,000 characters. MiniLM queries must reproduce the artifact's text or question recipe exactly. SigLIP 2 image artifacts can accept a text query only when `compatible_siglip2_spaces` confirms the same model revision, weight digest, projected dimension, pooling, normalization, and metric. A real MiniLM query for a saved CLEVR question reproduced its stored 384-dimensional vector exactly; a SigLIP 2 text query against the registered image artifact produced a normalized 768-dimensional vector. The receipt records both checks without storing the query text.

`compare.fields` accepts `left_field`, `right_field`, and `kind` (`correlation`, `crosstab`, or `grouped_numeric`). Its `provenance.comparison` includes denominators, missingness, population scope, sample unit, selected IDs, and the result. Null values are excluded pairwise, rather than coerced to zero. `import.research` accepts bounded JSON rows by exact stable ID, `prediction.<name>` field ID, an output kind (`scalar`, `categorical`, `vector`, `region`, `response`), explicit `source_reference`, and publication `rights`. It rejects duplicate/out-of-selection IDs, mixed units, non-finite values, vector dimension errors, malformed boxes, and oversize payloads. Missing selected rows become `not_applicable`; import does not execute source code or assert that results were independently reviewed.

The bounded local acceptance receipt is `reports/analysis-demo-clevr-100.json`; reproduce it after explicit local model preparation with `python -m dataset_atlas.processors.demo --root /path/to/DatasetAtlas`. It uses one source question for each of 100 locally available images in the pinned third-party CLEVR validation subset, with the source JSON checksum verified against the dataset registry. The four model weights have full SHA-256 receipts in the script and report. Ten JobManager runs completed 100/100: quality, NudeNet, COCO detection, MiniLM question embeddings, SigLIP 2 image embeddings, PCA, UMAP, k-means, original-space kNN outliers, and a source-answer versus detector-count grouped comparison. The stored artifacts were serialized, reloaded, and imported through verified immutable copies into the main `work/jobs.sqlite3` and `work/artifacts` for the workbench. NudeNet returned zero detections for all 100 images; COCO returned 2–15 detections per image, all person counts zero. These are detector outputs on rendered CLEVR scenes, not ground truth object labels. MiniLM returned 384-dimensional vectors and SigLIP 2 returned 768-dimensional vectors. The UMAP receipt joins 100 coordinates to COCO detection counts by stable ID. A separate real LanceDB table searched the 17 source-answer `yes` examples with a prefilter and index bypass; its top five IDs matched direct cosine-distance computation. This is a prepared subset demonstration, not complete official CLEVR coverage.

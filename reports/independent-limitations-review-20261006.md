## Concrete defects and repair gates

### 1. Included selection media can disagree with its claimed original SHA-256 — open, repair pending

At the reviewed checkpoint, `src/dataset_atlas/exports/selection.py:79–84` copies an approved file and hashes it for the export manifest without comparing those bytes to the source `Asset.sha256`. Import checks the manifest but does not reconcile the included media with the asset's claimed checksum.

A synthetic reproduction measured a 2×2 red PNG, created an Asset with that checksum, replaced the source with a blue PNG, then exported and imported the selection. Both operations succeeded; the loaded Asset retained the red-file SHA-256 while its included file contained the blue-file bytes. This breaks original-byte provenance even though the exchange's own checksums are self-consistent.

**Closure:** reject changed measured originals at export; bind included media to measured Asset hashes at import; test both source mutation and a maliciously rehashed exchange. No real media needs to be inspected for these tests. SPEC §§8.5, 17.5, and 22.1 apply.

### 2. Portable Pack validation does not check embedded asset/artifact identities — open, repair pending

At the reviewed checkpoint, `src/dataset_atlas/exports/pack.py:18–28` checks Record dataset/release/snapshot identity and duplicate Record IDs, but does not check embedded Asset membership or Artifact snapshot/unit/record IDs.

A synthetic Pack exported and reimported successfully with an Asset belonging to another dataset/release and an Artifact referencing another snapshot and a nonexistent record. Pydantic schema validation and valid manifest hashes do not establish referential integrity.

**Closure:** enforce compatible assets, artifact units/snapshots/IDs, and consistent item/point identities in both directions. Preserve legitimate partial-artifact coverage explicitly. Add negative synthetic tests; successful roundtrip parity alone misses this defect. SPEC §17.5 applies.

### 3. Provider response byte limit is enforced after buffering — open, repair pending

At the reviewed checkpoint, `src/dataset_atlas/providers/service.py:130–138` eagerly calls `client.post` and checks the 1 MB limit only after the full response is read. A mocked chunked stream consumed **2,000,000 bytes** before the advertised **1,000,000-byte** cap rejected it. Socket-operation timeouts also do not, by themselves, provide an absolute conversation deadline.

**Closure:** stream and check cumulative received bytes and the absolute deadline before accepting further chunks; retain redacted error behavior and reject redirects. Test an oversized stream and a slowly arriving stream without network access. Until then, describe the cap as a post-read acceptance limit, not bounded response allocation/transfer. SPEC §§14.2 and 17.1 apply.

### 4. Tool timeout returns while its worker continues — open limitation

`src/dataset_atlas/providers/service.py:457–474` runs the trusted tool backend in a daemon thread. The caller's deadline only bounds waiting on its queue. A synthetic backend was still running when a 0.01-second deadline returned an error, and completed at 0.08 seconds afterward.

The allowlisted tools remain read-only, but a timed-out lookup can continue preparation/media resolution and resource consumption; repeated timeouts can accumulate workers. Calling this hard cancellation would be inaccurate.

**Closure:** a cancellable backend contract with deadline propagation through query/media reads, or an isolated terminable worker plus bounded admission, must establish that work stops. Otherwise retain this as an explicit resource-enforcement gap. Test continuation after timeout and repeated admission. A shorter `Queue.get` timeout alone does not fix it. SPEC §§14.2 and 16 apply.

### 5. Transfer-budget sampling requires an explicit bias disclosure — open, repair pending

At the reviewed checkpoint, `remote_sample.py:85–92` describes budget-rejected draws as row groups selected with probability proportional to row count. A group larger than the budget has zero inclusion probability; differing byte costs also condition which later groups can enter. The code's existing synthetic test confirms that an oversized group supplies no rows.

This is acceptable bounded browsing when disclosed, but it is not an unbiased whole-population prevalence sample. Record budget conditioning and rejected draws, avoid the unconditional PPS interpretation, and keep source/shard sampling, availability exclusions, subset filtering, and primary-asset grouping visible. Deterministic IDs establish reproducibility, not statistical representativeness. SPEC §§5 and 9.4 apply.

### 6. Metadata tools and run estimates eagerly prepare media — open, code-path finding

At the reviewed checkpoint, `api/app.py:831` supplies `find_record` to `make_tool_backend`. Its default is `prepare_media=True` (`app.py:280`), and `api/tools.py:13` eagerly invokes it for every tool, including metadata-only description and aggregation. `prepared_record` can resolve/download missing original media. None of those tool result shapes requires original pixels. This allows a model's read-only metadata request to initiate media retrieval, contrary to SPEC §14.2's user-action boundary for downloads.

`POST /runs/estimate` likewise calls `selection_records(selection)` with media preparation enabled (`app.py:760`), before the unchanged-budget confirmation for `/runs`. The manager then reports `expected_download_bytes=0`. For beyond-preview populations, this can hide a transfer that already happened during estimation. This is a code-path finding; the reviewer deliberately did not trigger any real source/media lookup.

**Closure:** supply metadata-only lookups to tools; estimate canonical records without fetching originals; expose an explicit bounded media-preparation budget before execution, with an estimate identity that remains valid after transport paths are materialized. Test synthetic missing-media records with a resolver counter and confirm description, context without selected images, and estimation do not initiate a download. SPEC §§8.4, 14.2, and 16 apply.

# Reports

Dated verification receipts and the coverage matrix. A receipt records what was checked, when, and its limits; it is evidence, not approval.

- **Current state:** `final-status.json`, `dataset_coverage.csv` (one row per catalogue entry, regenerated by `scripts/report_prepared_workspace.py`), `release_evidence.md`, `acceptance_matrix.md`, `identity_review_queue.md`.
- **Per dataset:** `<dataset>-live-verification-*.json` records the counts, bytes moved and live reads for one integration (for example `bbq-v-…`, `multitrust-…`).
- **Storage:** `storage-reclaim-plan-20261009.md` and the footprint and cleanup receipts.
- **Browser and smoke runs:** `browser-*.json`, `complete-index-smoke-*.json`, `preview-media-smoke-*.json`.
- **Security and review:** `security-review-20261009.md`, `independent-review-brief-20261009.md`.
- **Everything with an older date** is history. Counts in an older receipt describe the tree of that day, not the current catalogue.

Receipts contain the maintainer's workspace paths; they are not a template for anything private.

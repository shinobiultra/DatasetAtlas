# Remaining implementation roadmap

Updated 2026-10-01. SPEC.md remains the acceptance contract. The catalogue-wide request is **not finished**: 333 catalogue entries, 169 with prepared previews in the maintainer's workspace, 164 canonical full-population indices there. An index covers its explicitly pinned population, not all historical releases or an unidentified paper subset.

## Shipping to colleagues (new this pass)

A colleague can now install a wheel, create a workspace with `atlas init`, and obtain previews from each publisher without the maintainer's files. [Evidence and the per-dataset table](reports/preview-reproducibility.md): **42 datasets fetched from an empty workspace and verified, 92 more with a ready source plan, 131 of the maintainer's 169 previews reproducible from the catalogue alone, 38 that still need a recipe.**

- A workspace states what it holds. The tracked registry recorded 98 previews as ready that failed to open on any other machine; availability is now computed per workspace (`on_request` vs `local`), and unfetched previews are offered, never shown as browsable.
- `atlas previews status|fetch` plans every dataset, fetches the cheapest first within a total download budget, resumes, and writes a receipt. The dataset page offers **Get preview** with the cost shown first. A new `auto` mode picks a small complete download, else a sampled remote read.
- `atlas datasets add|inspect|remove` and the catalogue's **Add dataset** dialog register a researcher's own folder, archive, CSV/TSV/JSONL/JSON/Parquet table or Hugging Face URL, built by the same pipeline as catalogue data. They live outside version control (`local-config/registry/`, `origin: user`), cannot shadow the catalogue, and can never be published.
- The wheel embeds the catalogue; `atlas init DIR` creates a workspace and `atlas init --update DIR` refreshes the shipped catalogue without touching the user's data. Version 0.2.0.
- Snapshot IDs for acquired data are derived from what was acquired (file checksums, revision, recipe, scope), not from the workspace, so two colleagues preparing the same bytes get the same ID and can exchange selections. A recipe may declare a reviewed ID; MNIST, EuroSAT, Imagenette, IdenProf, PAIRS, ArtBench and COCO val2017 now reproduce the maintainer's snapshot IDs exactly.
- Defects found only by working from an empty workspace, now fixed with regression tests: a cold-start race that returned HTTP 500 for the first media requests (concurrent SQLite cache creation); declared numeric CSV fields never cast (and one wrong declaration this exposed, `pairs-csv`'s `R_user`); Dropbox's per-request random redirect subdomain refused by the exact-host allowlist (now an explicit `*.suffix` entry); an unmeasurable storage root reported as "insufficient space". A Playwright suite (`e2e/fresh-workspace.spec.ts`) exercises a colleague's first run on an empty workspace.

Remaining work:

1. **Reproducibility of the maintainer's remaining 38 previews.** They were built from hand-placed sources or ad-hoc conversions with no recipe: GLUE (CoLA/QNLI/QQP/WNLI/MRPC/SST-2) and CEBaB, BBQ, HaluEval, BeHonest, Alpaca, Anthropic red-team, MaliciousInstruct and TDC2023 need their conversions turned into reproducible, verified converters; COCO 2014 images, VQA v2, POPE, GQA and CLEVR full need ZIP range access rather than multi-GB downloads (the adapters currently require the whole local archive); STL-10, EMNIST-balanced and SVHN need extraction support or a different source (SVHN's only source is plain HTTP, which the HTTPS-only fetcher refuses). These are implementation gaps, not source restrictions.
2. **Verify the 92 planned fetches.** Each has a ready plan and a pinned source; about 7% of the first 41 verified fetches failed before the defects above were fixed. A budgeted run is recorded in `reports/preview-reproducibility.md`; the rest should be verified before relying on them.
3. **Finish acquisition and adapter coverage for the 164 entries with no preview anywhere.** Many are aliases or variants of datasets already covered (several COCO, ImageNet, CUB and Flowers entries); others need identity research or are gated (ImageNet, FLICKR30K, LAION-scale collections) or unreleased. Accessible remaining examples include additional multimodal benchmarks. This is implementation work, not an external access restriction, wherever the report does not say otherwise.
4. **Exact release reconciliation.** All 64 papers have full-text mention inventories and all 332 canonical corpus groups have research dispositions, but that does not resolve every source, revision, variant or split. Preserve uncertain identities and source evidence; do not merge similarly named populations without evidence.
5. **Large remote releases.** FineVision's native shards total about 4.65 TB; DataComp metadata is about 340 GB. Selective remote Parquet indexing and sampled previews work with real multi-shard verification; catalogue-wide large-source coverage remains incomplete.
6. **Provider and publication evidence.** Local vLLM image/text/tool integration and LM Studio image/text integration passed on the maintainer's machine; capabilities are recorded per tested model. Only the existing CLEVR, PAIRS and EuroSAT public media packs are approved; additional publication requires source-specific review. No remote site deployment has been performed.
7. **Housekeeping on the maintainer's machine.** `local-config/storage.json` lists an external root that no longer exists (an LM Studio model folder). Storage admission fails closed on it, so new preparations in that workspace are refused until it is removed with `atlas storage configure`.

Validation and exact acquisition receipts: `reports/on-demand-preparation.json`, `reports/on-demand-live-verification.json`, and `reports/on-demand-implementation.md`. No sub-agents or paid APIs were used for this implementation.

## Concrete implementation findings

1. **API scope and local media checks pass adversarial fixture tests.** `tests/test_api_review.py` covers an 11 MB chunked POST without Content-Length, validation-error redaction, a computed-result filter over a complete-only record, saving and exporting that selection, root escapes, a symlink swap, and a model tool requesting IDs outside its approved context. The responses preserve run, partial, item, and returned-count semantics. This does not prove behavior for every ASGI deployment, adapter, or model server.
2. **Real complete-query and cancellation paths have measured receipts.** The [query timings](query-performance.json) cover exact count and first-page retrieval from a 999,968-record CLEVR index (three warm-OS-cache queries: 0.161–0.173 seconds) plus six smaller complete indexes; measured process peak was about 930 MiB. A [real CLEVR cancellation](query-cancellation.json) returned 33 ms after interrupt request and left the reader usable. DuckDB's 256 MB setting and the default 30-second timer do not bound total process RSS, source indexing, model jobs, or browser disconnect handling. Static/workbench query parity covers 14 cases and the 64-node boolean-AST boundary; broader null, mixed-type, cursor-drift, and nested-filter cases remain to evidence.
3. **The 10,000-item browser fixture exposed an unstable pagination assertion.** The synthetic 10,000-point map rendered and lasso selection reached the DOM in 44.6 ms on Chrome 153/Core Ultra 9 285HX. The synthetic 10,000-record grid/table held 48 cards or rows per page and zero table images. A rerun failed because the second page's 48 image requests arrived after the test sampled its request count and before its final equality assertion: sampled counts were 48 then 96. Wait for those requests or assert the bounded final count. Neither synthetic test proves real 10,000-record dataset coverage or GPU paint time. The [live browser report](browser-verification.md) covers narrower real preview flows.
4. **Run durability and path/network safety have meaningful checks, with resource limits still open.** `POST /runs/estimate` reports selected/unique asset counts and an output budget; a run requires an unchanged estimate digest. Workers stage immutable outputs without writing SQLite, and the coordinator rejects invalid or oversized staged files. Real CLEVR/COCO analysis and cancellation/restart tests support durable partial status and successful-item reuse. Peak processor allocation precedes serialization checks, so output limits do not constitute RSS/CPU limits. Descriptor-relative `O_NOFOLLOW` reads guard API media, provider/processor images, and model inputs. The allowlisted HTTPS fetcher and revision-keyed cache pass private-address, redirect, interrupted-transfer, pinning, and eviction tests; an end-to-end remote-adapter/browser prefetch receipt remains.
5. **Local model integration and exported artifacts are real but scoped.** A pinned local Qwen2.5-VL-3B service passed text, image, structured-output, and tool routing probes; its embeddings endpoint returned 404 and is marked unsupported. A saved CLEVR answer was wrong, and the independent two-record evaluation's latest answers were both wrong. This proves context routing and receipt persistence, not prediction accuracy. Ten 100/100 CLEVR and fourteen 100/100 COCO analysis runs have immutable source-linked artifacts; a portable CLEVR analysis pack exists. These are subset analyses.
6. **The publication and clean-install receipts need refreshing after catalogue changes.** The live publication manifest approves CLEVR, PAIRS, and EuroSAT preview records, with CLEVR derived artifacts allowlisted. A [clean Python 3.12 base-wheel installation](installation-verification.json) outside the checkout served a 100-record CLEVR pack and media without optional model libraries, scanned archive exclusions, and passed selected HTTP routes. That build captured an earlier 339-entry catalogue before alias consolidation, the five new child manifests, and later audits. The live registry also has 339 entries but different content. Rebuild and recheck the final archive from current registry bytes. No external deployment is claimed.
